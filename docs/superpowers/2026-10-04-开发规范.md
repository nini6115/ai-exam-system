## 1. 技术栈约束

| 分类 | 技术选型 | 版本 / 说明 |
|---|---|---|
| 语言 | Java | 17 |
| 框架 | Spring Boot | 3.2.5 |
| ORM | MyBatis-Plus | 3.5.x |
| 数据库 | MySQL | 8.0+，utf8mb4 |
| 数据库迁移 | Flyway | 10.10.0 |
| 缓存 | Redis | StringRedisTemplate |
| 定时任务 | Quartz | 后续模块引入 |
| 权限 | Token 拦截器（当前）→ Shiro（后续） | 粗粒度 → 细粒度演进 |
| 参数校验 | Jakarta Validation | Spring Boot 自带 starter |
| 工具 | Lombok | - |

**MyBatis-Plus 使用约束：**
- 单表 CRUD 用 `BaseMapper<T>` + `IService<T>`，不手写简单增删改查
- **复杂联表查询必须写在 XML 里**，不用 QueryWrapper 拼联表 SQL
- 禁止用代码生成器批量生成整套模块代码（可以生成 Entity/Mapper 骨架，业务代码手写）
- 逻辑删除用 `@TableLogic` 注解，字段名 `deleted`
- Entity 加 `@TableName("表名")`、主键加 `@TableId(type = IdType.AUTO)`

**约束：**
- 禁止随意引入新依赖，加依赖需团队确认
- 禁止升级核心框架版本（Spring Boot / Java），除非有明确理由

## 2. 分层规范

### 2.1 分层职责

| 层级 | 职责 | 禁止 |
|---|---|---|
| **Controller** | 接收请求、参数校验（DTO + Validation）、调用 Service、组装 AjaxResult 返回 | 写业务逻辑、直接调 Mapper / ServiceImpl、手写 try-catch 包错误 |
| **Service（接口 + Impl）** | 业务逻辑、事务控制、参数二次校验、调用 Mapper | 直接操作 request/response、组装 AjaxResult |
| **Mapper（接口 + XML）** | 数据库访问。单表 CRUD 继承 `BaseMapper<T>`，复杂联表写 XML | 写业务逻辑、跨业务域调用 |
| **Entity** | 数据库实体，与表一一对应，加 `@TableName`、`@TableId`、`@TableLogic` 注解 | 加业务方法、加非表字段（不含联表用的 collection） |
| **DTO** | 请求入参，放在 `dto` 包 | 当返回值用、直接返回给前端 |
| **VO** | 返回出参，放在 `vo` 包，脱敏处理 | 当入参用 |

> Service 实现层继承 `ServiceImpl<BaseMapper<T>, T>` 获得单表 CRUD 能力，复杂业务在 Service 层自行扩展。

### 2.2 包结构

```
com.aiexam.<模块名>/
├── controller/      # 控制器
├── service/         # Service 接口
│   └── impl/        # Service 实现
├── mapper/          # Mapper 接口
├── entity/          # 实体类
├── dto/             # 请求入参
└── vo/              # 返回出参
```

### 2.3 命名规则

| 类型 | 命名示例 | 说明 |
|---|---|---|
| Controller | `SysUserController` | 业务名 + Controller |
| Service 接口 | `SysUserService` | 业务名 + Service |
| Service 实现 | `SysUserServiceImpl` | 业务名 + ServiceImpl |
| Mapper 接口 | `SysUserMapper` | 表名 + Mapper |
| Entity | `SysUser` | 表名（大驼峰） |
| DTO | `LoginDTO` / `UserQueryDTO` | 业务含义 + DTO |
| VO | `LoginVO` / `UserVO` | 业务含义 + VO |

## 3. 统一返回格式 AjaxResult

所有接口必须返回 `AjaxResult<T>`。

### 3.1 结构

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 状态码：200成功，400参数错误，401未登录，403无权限，500系统错误 |
| msg | String | 提示信息 |
| data | T | 返回数据 |

### 3.2 使用方式

```java
// 成功（无数据）
return AjaxResult.success();

// 成功（带数据）
return AjaxResult.success(userVO);

// 失败（业务异常）
throw new RuntimeException("用户名或密码错误");
// → 全局异常自动捕获，返回 code=500, msg="用户名或密码错误"
```

### 3.3 分页返回格式

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "list": [],
    "total": 100,
    "pageNum": 1,
    "pageSize": 10
  }
}
```

用 `PageVO<T>` 封装：`{ List<T> list, Long total, Integer pageNum, Integer pageSize }`

## 4. 全局异常处理规范

入口：`com.aiexam.common.exception.GlobalExceptionHandler`

### 4.1 异常分类与对应状态码

| 异常类型 | code | 触发方式 |
|---|---|---|
| 业务异常 | 500 | `throw new RuntimeException("错误信息")` |
| 参数校验异常 | 400 | DTO 上的 Validation 注解 |
| 鉴权失败 | 401 | Token 拦截器直接写 response |
| 兜底异常 | 500 | 所有未捕获的 Exception |

### 4.2 使用原则

- ✅ 业务错误直接 `throw new RuntimeException("提示信息")`
- ✅ 参数校验用 `@NotBlank`、`@Size` 等注解放在 DTO 字段上
- ❌ 禁止在 Controller 里 `try-catch` 然后返回 `AjaxResult.error()`
- ❌ 禁止自定义一堆异常类，基础阶段 RuntimeException 够用了

## 5. Token 鉴权规范

### 5.1 Token 传递

- 请求头：`Authorization: <token>`
- 不加 `Bearer ` 前缀，简单直接

### 5.2 Token 存储

- Redis Key：`login:token:{token}`
- Value：userId（字符串）
- 有效期：2 小时（7200 秒）
- 续期策略：当前不自动续期，后续按需加

### 5.3 拦截器实现

| 项 | 内容 |
|---|---|
| 拦截器类名 | `com.aiexam.common.interceptor.TokenInterceptor` |
| 实现接口 | `HandlerInterceptor` |
| 配置类 | `com.aiexam.config.WebMvcConfig`（实现 `WebMvcConfigurer`） |
| 拦截路径 | `/**` |
| 白名单路径 | `/user/login`、`/user/captcha` |

**校验流程：**
1. 从请求 Header 取 `Authorization`（值即 token，无 `Bearer ` 前缀）
2. token 为空 → 返回 401 `{"code":401, "msg":"未登录"}`
3. Redis 查 `login:token:{token}`，不存在 → 返回 401
4. 存在 → 取 userId，查用户信息，放入 `UserContext`（ThreadLocal）
5. 放行，进入 Controller
6. `afterCompletion` 中清理 ThreadLocal，防止内存泄漏

**401 返回格式：** 直接用 response 写 JSON，ContentType 为 `application/json;charset=UTF-8`，code=401。

### 5.4 当前登录用户 ThreadLocal

| 项 | 内容 |
|---|---|
| 工具类名 | `com.aiexam.common.context.UserContext` |
| 存储方式 | `ThreadLocal<LoginUser>` |
| LoginUser 字段 | `userId`、`username`、`realName` |

**核心方法：**
- `static LoginUser get()` — 获取当前登录用户对象
- `static Long getUserId()` — 获取当前用户ID
- `static String getUsername()` — 获取当前用户名
- `static void set(LoginUser user)` — 设置（拦截器调用）
- `static void clear()` — 清理（拦截器 afterCompletion 调用）

> 业务代码中直接 `UserContext.getUserId()` 取当前用户ID，无需传参。

### 5.5 权限粒度（当前阶段）

- 粗粒度：所有管理接口只要登录 + admin 角色就能访问
- 通过在 Service 层判断当前用户角色实现
- 后续引入 Shiro 后再细化到接口级权限注解

## 6. 数据库规范

### 6.1 表命名

- 格式：`模块前缀_表名`，全小写下划线
- 系统类：`sys_` 前缀（sys_user、sys_role、sys_user_role）
- 业务类：业务前缀（exam_paper、question、answer_sheet）
- 关联表：`表1_表2`（sys_user_role、exam_paper_question）

### 6.2 字段命名

- 全小写下划线，如 `create_time`、`real_name`
- 主键：`id BIGINT AUTO_INCREMENT`
- 外键：`关联表_id`（如 `user_id`、`paper_id`）
- 状态类：`status`（tinyint），枚举值加注释
- 布尔类：不用 is_ 前缀（防止 getter/setter 混乱），用 `deleted`、`enabled` 等

### 6.3 必备字段

所有业务表必须包含：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| create_time | DATETIME | CURRENT_TIMESTAMP | 创建时间 |
| update_time | DATETIME | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| deleted | TINYINT | 0 | 逻辑删除：0未删 1已删 |

### 6.4 索引命名

| 索引类型 | 命名格式 | 示例 |
|---|---|---|
| 主键 | PRIMARY | - |
| 唯一索引 | `uk_字段名` 或 `uk_表缩写字段1_字段2` | `uk_username`、`uk_user_role` |
| 普通索引 | `idx_字段名` 或 `idx_字段1_字段2` | `idx_creator`、`idx_status_time` |

### 6.5 引擎与字符集

- 引擎：InnoDB
- 字符集：utf8mb4，排序规则 utf8mb4_unicode_ci

### 6.6 迁移脚本

- 路径：`src/main/resources/db/migration/`
- 命名：`V{版本号}__{描述}.sql`（两个下划线）
- 版本号递增：V1、V2、V2.1...
- **禁止修改已发布的脚本**，修改要写新版本

## 7. 编码规范

### 7.1 注释

- 类上必须写用途说明（单行或 JavaDoc）
- public 方法写 JavaDoc（参数、返回值、异常）
- 复杂逻辑写行内注释，说明"为什么"而不是"做什么"
- 简单 getter/setter 不用写注释
- SQL 复杂查询在 XML 里加注释

### 7.2 日志

- 用 SLF4J + Lombok `@Slf4j` 注解
- Controller / Service 入口方法打 info 日志（操作人+操作内容）
- 异常打 error 日志（带异常栈）：`log.error("xxx失败", e)`
- 敏感信息（密码、token、身份证）**严禁**打日志
- 大对象不直接 toString 打日志，防止刷屏

### 7.3 命名

| 类型 | 规则 | 示例 |
|---|---|---|
| 类名 | 大驼峰 | `SysUserService` |
| 方法名 | 小驼峰，动词开头 | `getUserById`、`createUser` |
| 变量名 | 小驼峰 | `userName` |
| 常量 | 全大写下划线 | `MAX_PAGE_SIZE` |
| boolean 变量 | 不用 is 前缀 | `deleted`、`enabled` |

## 8. 分页规范

### 8.1 请求参数

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| pageNum | Integer | 1 | 页码，从 1 开始 |
| pageSize | Integer | 10 | 每页条数，最大 100 |

### 8.2 返回结构

```java
@Data
public class PageVO<T> {
    private List<T> list;      // 数据列表
    private Long total;        // 总条数
    private Integer pageNum;   // 当前页
    private Integer pageSize;  // 每页条数
}
```

### 8.3 实现方式

- 使用 **MyBatis-Plus 的 `Page<T>` 对象**进行分页查询
- Service 层构造 `Page<T> page = new Page<>(pageNum, pageSize)`
- Mapper 方法第一个参数为 `Page<T>`，返回 `IPage<T>`
- 复杂联表分页查询写在 XML 里，MyBatis-Plus 自动 count
- Controller 层把 `IPage<T>` 转成 `PageVO<T>` 返回

```java
// Service 层示例
Page<UserVO> page = new Page<>(pageNum, pageSize);
IPage<UserVO> result = userMapper.selectUserPage(page, queryDTO);

// 转 PageVO 返回
PageVO<UserVO> vo = new PageVO<>();
vo.setList(result.getRecords());
vo.setTotal(result.getTotal());
vo.setPageNum(pageNum);
vo.setPageSize(pageSize);
```

## 9. Redis Key 规范

### 9.1 命名格式

```
模块:业务:标识
```

- 全小写，冒号分隔
- 示例：
  - `login:token:abc123` — 登录 token
  - `login:captcha:uuid` — 验证码
  - `user:info:123` — 用户信息缓存

### 9.2 使用原则

- 缓存必须设置过期时间，不永久存储（除非特殊场景并加注释说明）
- 缓存穿透：空值也设短期过期
- 缓存更新：先更数据库，再删缓存（Cache Aside 模式）

## 10. 禁止事项

| # | 禁止 | 原因 |
|---|---|---|
| 1 | Controller 直接调 Mapper | 分层混乱，业务散落在各处 |
| 2 | Controller 里写业务逻辑 | 职责不清，无法复用 |
| 3 | 自己 try-catch 包 AjaxResult.error | 绕过全局异常，错误码不统一 |
| 4 | Entity 里加业务方法 | 实体应该是纯数据对象 |
| 5 | 返回密码、token 等敏感字段给前端 | 安全隐患 |
| 6 | 修改已发布的 Flyway 脚本 | 环境不一致，迁移失败 |
| 7 | 随意引入新依赖 | 依赖膨胀，维护成本高 |
| 8 | 用 QueryWrapper / LambdaQueryWrapper 拼联表查询 | 联表 SQL 必须写在 XML 里，可读性和维护性更好 |
| 9 | 用代码生成器批量生成整套模块代码 | 生成的代码臃肿，不符合分层规范。Entity/Mapper 骨架可生成，业务代码手写 |
| 10 | 日志里打印密码、token 等敏感信息 | 安全隐患 |
| 11 | 用 is 前缀命名 boolean 变量 | 序列化/getter 容易出问题 |

## 11. 前后端分离架构

### 11.1 整体结构

- 前端：独立 Vue 项目（vue-element-admin 或 RuoYi-Vue 风格），独立端口启动
- 后端：Spring Boot 项目，端口 8080，提供 REST API
- 通信：JSON over HTTP，前端通过 Axios 调用后端接口
- 部署：前端打包后由 Nginx 托管，后端独立部署，Nginx 反向代理

### 11.2 接口前缀规范

- 所有后端接口统一加 `/api` 前缀（Spring Boot `server.servlet.context-path: /api`）
- 示例：`/api/user/login`、`/api/user/list`、`/api/exam/paper/list`
- 模块路径紧跟前缀之后：`/api/{模块}/{资源}/{动作}`

### 11.3 跨域处理

- **开发阶段**：Vue 配置 `devServer.proxy`，把 `/api` 转发到 `http://localhost:8080`
- **生产环境**：Nginx 反向代理，`/api` 路径转到后端服务
- **后端不配 CORS**，通过代理解决，避免安全风险

### 11.4 前端约定

| 项 | 约定 |
|---|---|
| Token 存储 | `localStorage`，key = `ai_exam_token` |
| 请求 Header | `Authorization: <token>`（不加 Bearer 前缀） |
| 401 处理 | Axios 响应拦截器统一处理，清除 token，跳登录页 |
| 响应解析 | 统一按 `AjaxResult` 结构解析，code===200 视为成功 |
| 错误提示 | 后端返回的 `msg` 字段直接展示 |
| 分页参数 | `pageNum`、`pageSize`，与后端保持一致 |

### 11.5 接口设计原则

- RESTful 风格：GET 查、POST 增、PUT 改、DELETE 删
- 资源名复数：`/api/users`、`/api/exams`（当前模块沿用已有 `/api/user` 风格，后续模块统一）
- 批量操作：`/api/user/batchDelete` 等动作式路径

## 13. 核心业务流程

### 13.1 登录流程

1. **获取验证码**：前端 `GET /api/user/captcha`，拿到 `captchaKey` + `captchaImage`（base64），验证码存 Redis，有效期 120 秒
2. **提交登录**：前端 `POST /api/user/login`，携带 `username`、`password`、`captchaKey`、`captchaCode`
3. **后端校验**：验证码 → 用户存在 → 状态正常 → BCrypt 密码比对
4. **生成 Token**：UUID Token 存 Redis（key = `login:token:{token}`，value = userId），有效期 2 小时
5. **更新登录信息**：记录 last_login_time、last_login_ip
6. **返回结果**：`{ token, userInfo, roles }`
7. **前端存储**：Token 存 `localStorage`，后续请求 Header 带 `Authorization: <token>`

### 13.2 考试流程

1. **教师创建试卷**：智能组卷（按题型/难度/知识点随机抽题）或手动组卷，生成 `exam_paper` + `exam_paper_question`
2. **发布考试**：设置考试时间、防作弊参数（切屏次数、乱序、离开超时等），写入 `exam` + `exam_user`
3. **学生进入考试**：校验考试状态、考试次数、迟到限制，创建 `answer_sheet`，记录开始时间、IP、UA，生成题目乱序种子
4. **学生答题**：
   - 前端定时（如 30 秒）自动保存答案到后端
   - 切屏/离开页面实时上报，写 `cheat_record`，超限额触发强制交卷
   - 答题明细暂存 `answer_detail`（草稿态）
5. **交卷**：
   - 手动交卷 / 超时自动交卷 / 切屏超限强制交卷
   - 写 `answer_sheet.status` 和 `submit_time`
   - 超时任务用 Quartz 定时扫描
6. **判分**：
   - 客观题立即自动判分，写入 `answer_detail.score`、`is_correct`
   - 主观题调用大模型 API 判分（异步），结果存 `ai_score` 表
7. **教师复核**：人工审核主观题分数，可修正，生成最终成绩
8. **成绩发布**：更新 `answer_sheet.total_score`、`is_passed`，学生可查成绩

### 13.3 AI 判卷流程

1. **取待判数据**：从 `answer_detail` 取主观题（`graded_by IS NULL`、题型=简答）
2. **组装 Prompt**：题目 + 标准答案 + 评分标准 + 学生答案，要求 LLM 返回 JSON 格式 `{ score, comment }`
3. **调用大模型**：智谱/通义 API（可配置），流式或同步调用
4. **解析结果**：JSON 解析分数和评语，校验分数范围（0 ~ full_score）
5. **写入结果**：更新 `answer_detail.score`、`grade_comment`，`graded_by = 3`（AI）
6. **人工复核**：教师可在后台查看 AI 判分结果，可调整分数，调整后 `graded_by = 2`（人工）
7. **汇总成绩**：所有题目判完后，更新 `answer_sheet.subjective_score`、`total_score`
